# UniverseSolver

Оптимизатор сборок для Honkai: Star Rail, работающий в браузере и размещаемый на GitHub Pages.

## Запуск сайта

В Alpha 0.15 разделы связаны маршрутом **команда → билд → оценка реликвий → пересчёт команды**. Добавлены отдельные билды персонажей, оценка 5★ сабстатов относительно математического потолка, условная вероятность реролла, боевое A/B и локальная полезность статов. Есть четыре редактируемых тира целей: Ранний, Начальный (MoC 36 / PF 12 / AS 12), Средний (Starward), Высший (Арбитраж). Инструкция и границы точности — [RELIC_LAB.md](RELIC_LAB.md).

Раздел **«Команды»**: обязательный кор, необязательный пул, отдельные характеристики героев и событийная симуляция против 1–5 болванок с бесконечным HP, DEF 0 и RES 0%. Поддержаны все 98 записей каталога: 93 формы без гендерных дублей и пять женских вариантов Первопроходца. Аудит и границы расчёта — [FINAL_ROSTER.md](FINAL_ROSTER.md). Область поддержки — [TEAMS.md](TEAMS.md). Проверка: `node scripts/verify-teams.cjs`.

В оптимизаторе два режима: **«Комбинация»** перебирает реальные предметы, **«Сеты»** сравнивает бонусы 4-предметных наборов, 2+2 и планарок по симуляции при одинаковых характеристиках. Статы можно вычислить из текущих шести предметов с исключением бонусов сетов. Область поддержки — [SETS.md](SETS.md). Проверка: `node scripts/verify-sets.cjs`.

В билд-оптимизаторе выбор персонажа, конуса, слота и набора реликвий выполняется через карточки с оригинальными иконками и поиском.

Добавлен раздел **«Оптимизатор»**: инвентарь реликвий 5★, выбор персонажа/конуса/действия, условия боя, ограничения, точный перебор, top-10 и сравнение с текущей сборкой. Работает локально и на GitHub Pages. Это первая модель прямого удара; область поддержки и инструкция — в [OPTIMIZER.md](OPTIMIZER.md). Проверка ядра: `node scripts/verify-optimizer.cjs`.

Справочная часть: 98 записей персонажей и форм, 170 конусов и 62 набора реликвий из зафиксированного снимка StarRailRes. Доступны поиск, фильтры, характеристики по уровням и возвышениям, навыки с выбором уровня, следы, эйдолоны, наложения конусов, предметы наборов и значения характеристик реликвий.

Для просмотра откройте `index.html` в браузере. Данные включены в `data/game-data.js` и не требуют API или сервера. Для иллюстраций и шрифта нужен интернет; изображения загружаются из [StarRailRes](https://github.com/Mar-7th/StarRailRes). Профили хранятся в localStorage браузера; для стабильного хранения используйте один и тот же адрес сайта.

Для GitHub Pages в Settings → Pages выберите Source: GitHub Actions. Workflow `.github/workflows/pages.yml` публикует сайт при push в `main` или ручном запуске. Публикация из рабочей копии пока не выполнялась.

## Источник и обновление базы

Источник: [StarRailRes](https://github.com/Mar-7th/StarRailRes), русские таблицы `index_new/ru`, английские имена персонажей для поиска. Снимок закреплён на ревизии `dbe8cdfcfb0bf657b9fe1cf92d5537f118ccb487`. Полнота ограничена источником; запись в базе не подтверждает релиз персонажа. Половые варианты Первопроходца и альтернативные формы сохранены отдельно.

Обновление: `node scripts/update-data.mjs <полный SHA ревизии>`. Скрипт загружает все таблицы до замены снимка. Проверка: `node scripts/verify-data.cjs` и `node --check app.js`.

Уточнения хранятся отдельно от исходного снимка в `data/supplements.js`. Недостающий параметр #5 в навыках духа памяти Кастории `1140710` и `1140711` дополнен значением 25% по [Prydwen](https://www.prydwen.gg/star-rail/characters/castorice), проверено 02.11.2026. Ссылки на источник показаны рядом с уточнением. Для нескольких персонажей добавлены краткие объяснения особого ресурса сверхспособности, сверенные с Prydwen. Остальные русские описания и уровневые коэффициенты остаются из StarRailRes: массовая выгрузка страниц Prydwen блокируется защитой сайта.

В карточке персонажа открывается вкладка «Кит»; отдельно доступны следы, E1–E6, характеристики и EX-эйдолоны. `HSR_SUPPLEMENTS.ex_eidolons` — независимый от E0–E6 словарь по ID персонажа с массивом объектов `{name, description, source}`. Пока подтверждённые записи в каталог не добавлены, вкладка показывает это явно. EX не считается E7 и не влияет на профиль или расчёты.

Оригинальные иконки Путей и стихий загружены с CDN Prydwen в `assets/icons`; повторная загрузка — `node scripts/download-icons.mjs`. В каталоге все фильтры представлены кнопками. Локальные иконки и данные включены в GitHub Pages workflow.

Характеристики персонажа и конуса считаются как `base + step × (level − 1)` для выбранного возвышения. Основные характеристики реликвий: `base + step × уровень`; дополнительные — значения одного ролла `base + step × tier`. Проценты в параметрах хранятся долями. Описания показывают справочные значения, без применения условий боя, экипировки и выбранных эйдолонов.

## Принцип

Программа знает игровые механики, но не содержит рейтингов сборок. Она рассчитывает допустимые варианты и сравнивает их по выбранной цели в одинаковых условиях.

## Первая версия: один персонаж

Оптимизируем сборку выбранного персонажа при фиксированных союзниках, противнике и сценарии действий. Поиск состава команды появится позже.

Входные данные:

- Персонаж, уровень, уровни следов и эйдолоны.
- Доступные световые конусы и их параметры.
- Собственные реликвии и планарные украшения: слот, набор, уровень, основная и дополнительные характеристики.
- Условия боя: противник, число целей, сопротивления, уязвимости и применимые эффекты союзников.
- Заданный сценарий действий и ограничения сборки, например минимальная скорость.

Результат:

- Лучшие найденные сборки по ожидаемому урону за заданный сценарий.
- Итоговые характеристики и расшифровка расчёта: эффекты, множители, вклад действий.
- Сравнение с текущей сборкой и прирост от каждой полной замены сборки.
- Оценка реликвий в контексте персонажа и сборки, без универсального балла по сумме характеристик.

Первый вертикальный срез: один полноценно реализованный персонаж, фиксированный световой конус и сценарий, ручной ввод реликвий, точный перебор допустимых сочетаний из небольшого инвентаря. Расширение конусов, эйдолонов и персонажей — после проверки расчёта.

## Оценка идеала

Сравниваем сборку с явно заданной достижимой верхней границей: допустимые основные характеристики, количество улучшений и значения дополнительных характеристик. Условия идеала должны отображаться пользователю.

Разрыв по урону вычисляется только для одной цели и одинаковых условий. Разрыв отдельного предмета оценивается через замену в сборке; он не является постоянным свойством предмета. Если верхняя граница найдена приближённым поиском, её нельзя называть доказанным идеалом.

## Архитектура

- `game-data`: версионированные игровые данные и источники; никаких рекомендаций по сборкам.
- `engine`: чистые функции характеристик, условий эффектов и расчёта действий, независимые от интерфейса.
- `scenarios`: персонажи, союзники, противники, последовательности действий и условия сравнения.
- `optimizer`: генерация допустимых сборок, оценка через engine, ограничения и лучшие результаты.
- `inventory`: локальное хранение предметов, импорт и экспорт.
- `ui`: ввод данных, управление поиском, сравнение и объяснение результатов.

Даже в первой версии расчёт получает контекст команды. Автоматический выбор союзников и поиск ротации не входят в первый этап.

## Ограничения поиска

Точный перебор небольшого инвентаря служит проверяемой основой. Ускорения добавляются с сохранением корректности: кэширование и доказуемое отсечение. Приближённые режимы должны явно обозначаться; лучший найденный результат нельзя выдавать за доказанный максимум.

## Размещение и проверка

Статическое приложение для GitHub Pages без обязательного сервера. Тяжёлый поиск выполняется в Web Worker с прогрессом и отменой. Пользовательские данные сохраняются в браузере и экспортируются в файл.

Перед расширением механик нужны проверяемые примеры расчёта урона и эффектов, а также сравнение результатов оптимизатора с полным перебором на небольших инвентарях. Игровые данные и формулы необходимо сверять с источниками при реализации и фиксировать их версию.
